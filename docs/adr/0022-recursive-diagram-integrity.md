# ADR-0022: Verify recursive diagram source and PNG integrity

- **Status:** Accepted
- **Date:** 2026-08-19
- **Deciders:** Alex Anglin
- **Supersedes:** none

## Context

The diagram gate inspected only `docs/architecture/*.dot` and recorded only the editable source hash.
Nested workflow diagrams could therefore bypass the full check, and a corrupted, replaced, or empty PNG
could pass as long as its DOT source was unchanged. That did not enforce the repository rule that both the
editable source and generated PNG are reviewable artifacts.

## Decision

Discover Graphviz sources recursively below `docs/architecture/` for both generation and full validation.
For every source, store labeled SHA-256 values for the DOT and PNG in `<source>.sha256`. Require the PNG
signature and both matching hashes. Treat changes to `.dot`, `.png`, or `.dot.sha256` as inputs to the
commit-stage diagram gate, mapping generated artifacts back to their source.

## Consequences

- Nested architecture and workflow diagrams receive the same validation as top-level diagrams.
- PNG corruption or manual replacement blocks a commit even when the source is unchanged.
- A Graphviz regeneration changes two recorded hashes and can produce a reviewable PNG diff.
- Sidecars generated by the previous one-hash format must be regenerated once.

## Alternatives considered

- **Keep source-only hashes.** Rejected: they cannot attest the generated artifact required by policy.
- **Compare file modification times.** Rejected: Git does not preserve them across clones.
- **Render and byte-compare in every commit hook.** Rejected: Graphviz version and font differences make
  rendering a poor fast-path dependency; explicit generation plus content integrity is deterministic.
