# ADR-0202: Accept the CycloneDX version the pinned Trivy emits

- **Status:** Accepted
- **Date:** 2026-08-28
- **Deciders:** Alex Anglin
- **Amends:** ADR-0162, as to the accepted CycloneDX specification version

## Context

[ADR-0162](0162-generate-and-validate-per-image-cyclonedx-sboms.md) requires one validated CycloneDX
software bill of materials for every pulled and built stack image, generated by the Trivy release
[ADR-0048](0048-scan-images-and-deploy-configuration-with-trivy.md) pins, and validated independently by
`tools/sbom_gate.py`. That record states the pinned Trivy generates CycloneDX 1.6, and the gate
therefore requires `specVersion` to equal `1.6` exactly.

That version was asserted rather than measured. The gate's first continuous-integration exercise, in
the `image scan` job of run 33225876416 on 2026-08-29, refused all nine image documents with the single
refusal `SBOM: specVersion must be 1.6`. Every other assertion in the same documents passed, including
the pinned-tool attestation, so Trivy identified itself as `aquasecurity/trivy` version `0.74.0` while
emitting a different specification version.

Measured directly against the same pinned release, `trivy --format cyclonedx` writes
`"specVersion": "1.7"` and `"bomFormat": "CycloneDX"`, with
`metadata.tools.components[0]` equal to `{"group": "aquasecurity", "name": "trivy", "version":
"0.74.0"}`. Trivy 0.74.0 exposes no flag that selects an output specification version: `--format`
accepts a format name only. The 1.6 in ADR-0162 was therefore never a property of the pinned tool.

## Decision

**`tools/sbom_gate.py` requires CycloneDX `1.7`, the version the pinned Trivy release actually emits.**

Nothing else in ADR-0162 changes. The gate still compares the version for exact equality rather than
accepting a range or a minimum, still fails closed on any other document, and still requires the
document to name the pinned Trivy release. The accepted version and the pinned tool remain two
independent assertions, so a document that names the pinned release while carrying an unexpected
structure is still refused.

The gate's own conformance tests carry the change: the accepted fixture is a 1.7 document, and the
refusal case now offers a 1.5 document and 1.6 in turn so the constant cannot drift without a red test.

## Consequences

- The first green `image scan` run is the first evidence that any generated image SBOM satisfies the
  complete gate. Until this change, no document had ever passed it.
- A Trivy upgrade that moves the emitted specification version still fails every image closed and
  requires this constant, its tests, and a record to move together. That is the behaviour ADR-0162
  asked for; it worked, and this is its first exercise.
- Negative: the accepted version is knowable only by measuring the pinned binary, because Trivy does
  not document it in a machine-readable form the gate could read. The pin in
  [ADR-0048](0048-scan-images-and-deploy-configuration-with-trivy.md) and this constant must move
  together, and a reviewer cannot verify the pairing from the source alone.

## Alternatives considered

- **Ask Trivy for CycloneDX 1.6.** Not available. Trivy 0.74.0's `--format` selects a format, not a
  specification version, and no other flag selects one.
- **Downgrade the pinned Trivy to a release that emits 1.6.** Rejected because ADR-0048 pins Trivy for
  its scanning behaviour and its advisory database currency; moving that pin backwards to obtain an
  older document version would trade a security property for a formatting one.
- **Accept any version at or above 1.6.** Rejected because ADR-0162 chose exact equality so that an
  upstream format change is a visible decision rather than a silent one, and a range would have hidden
  exactly the change this record is making.
- **Validate against the published CycloneDX JSON Schema instead of a version constant.** Rejected here
  because it adds a network-fetched or vendored schema and a validator to a gate whose value is that it
  is a small, fail-closed, offline reader. ADR-0162 already weighed and rejected that dependency.
